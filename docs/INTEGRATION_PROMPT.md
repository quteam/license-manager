> 接口契约以 [API.md](API.md) 为准，字段、路径、响应结构不得自行猜测。

请帮我完成一个"软件卡密授权接入"的开发任务。我会提供项目源码和接口文档，
请你先自行阅读、理解，再动手实现。

【第一步：阅读理解（务必先做）】
1. 请先浏览我提供的项目源码目录，判断这个项目的技术栈、语言、框架、
   项目结构和入口文件位置，并简要说明你的判断（一两句话即可）。
2. 请阅读我提供的 API 文档（api.md），完全按照文档中的接口契约

【任务目标】
为这个软件接入卡密（激活码）验证系统，实现以下功能：
1. 激活功能：软件启动时如果检测到本机没有有效的授权信息，显示一个
   "输入激活码"的界面，用户输入卡密后调用激活接口；成功则放行进入软件，
   失败则用通俗易懂的中文提示原因（区分：卡密无效、已过期、已被禁用、
   已绑定其他设备、解绑次数用完等）。
2. 启动校验：软件每次启动时调用校验接口验证授权是否仍然有效，有效放行，
   无效给出对应提示。
3. 本地保存：激活成功后把卡密和授权信息（到期时间等）持久化保存到本机，
   下次启动直接读取，无需用户重复输入。
4. 换机解绑：在软件里提供"解绑设备"功能入口，用户换电脑前可以解绑，
   便于在新设备重新激活。
5. 设备指纹：实现一个获取本机稳定设备标识的方法（如机器码、硬件序列号等），
   用于接口中的 device_fingerprint 字段。
6. 集成方式：按这个项目最合适的原生方式集成（例如：桌面软件用主窗口/弹窗，
   Web 用页面/组件，命令行工具用交互提示），不要破坏项目现有的功能和结构。
7. 购买引导：在"输入激活码"页面（激活界面）上始终显示"去购买/立即购买"
   按钮或链接，引导用户购买卡密；卡密过期、无效、被禁用等校验失败场景的
   提示界面同样显示该按钮。注意：购买链接不在 activate/verify/unbind-device
   接口的响应中，需要通过 /api/client/app-info 接口获取（请求体传 app_id 和
   app_secret，响应 data 中有 purchase_url 字段）。实现要点：
   a) 激活界面加载时（以及校验失败时）调用一次 /api/client/app-info
      获取 purchase_url，并缓存到本地（应用启动期间只请求一次即可）；
   b) 若 purchase_url 存在，在激活页面（无论用户是否已输入卡密）常驻显示
      "去购买"按钮或链接，点击用系统浏览器打开该链接；若为空则不显示；
   c) app-info 接口失败时静默降级（不阻塞主流程，仅不显示购买按钮）；
   d) 若用户未在后台配置购买链接，软件不报错、正常使用即可。

【版本更新接入（建议实现）】
在实现上述功能的同时，建议为客户端增加版本更新检查：
1. 启动时（或定时）调用 POST /api/client/versions/latest（请求体含 app_id、app_secret、
   current_version_code），也可以直接复用 /api/client/app-info 响应中的 latest_version
   字段，无需额外请求。
2. 若 latest 存在且 latest.version_code > current_version_code：
   - latest.is_forced 为 true：必须更新，提示用户前往 latest.download_url 下载新版本，
     阻止继续使用；
   - latest.is_forced 为 false：提示用户可更新（可选）。
3. 若 latest 为 null 或已是最新版本，不打扰用户。
4. 更新说明 release_notes 为 Markdown 文本，可在更新弹窗中渲染展示。
5. 接口调用失败时静默降级（不阻塞软件主流程，仅不提示更新）。

【实现要求】
1. 改动最小化：只新增必要的文件和修改必要的位置，不要大改现有代码结构，
   不要动与授权无关的功能。
2. 代码完整可运行：每个文件给完整代码，不要用省略号或伪代码。
3. 错误处理：网络超时、服务器不可用、返回异常时，软件不能崩溃，要给出
   友好的降级提示（例如"网络异常，请稍后重试"）。
4. 如果需要新增依赖，列出具体的安装命令，并说明安装后如何验证。
5. 改完后用简洁的清单告诉我：新增/修改了哪些文件、每处的作用、
   我需要在后台做什么配置（如有）。
6. 如果发现接口文档与源码里实际定义不一致，以接口文档为准并提醒我。
