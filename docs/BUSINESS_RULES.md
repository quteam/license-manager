# 业务规则

本文是产品范围、领域术语和授权状态语义的规范来源。实现主要位于 `worker/src/service.ts`，持久化条件位于 `worker/src/repository.ts`，行为变更必须由测试证明。

## 产品边界

当前产品提供：

- 多应用、多平台授权管理。
- 应用创建、编辑、启用/禁用、密钥更换和受限删除。
- 激活码批量生成、查询、筛选、禁用/启用和软删除。
- 周卡、月卡、季卡、年卡四类内置套餐。
- 客户端获取应用信息、激活、校验和自助解绑迁移。
- 管理员登录、JWT 会话、密码修改和 bootstrap 密钥恢复。
- 租户隔离、超级管理员租户管理和租户管理员业务后台。
- 管理后台统计、操作日志、接入文档、SDK 示例和 Playground。

当前不包含以下能力。新增前必须先明确租户、数据模型、鉴权和兼容性影响：

- 租户内细粒度权限和自定义角色。
- 支付、订单、发票或财务结算。
- 明文激活码找回。
- 可安装 SDK 包发布、版本兼容矩阵或强制升级策略。
- 多数据库或非 Cloudflare 部署适配。

## 领域术语

| 术语 | 含义 |
| --- | --- |
| 应用（App） | 一个独立授权产品，拥有公开 `app_id`、私有 `app_secret`、平台和启用状态 |
| 租户（Tenant） | 应用及其授权数据的隔离边界，状态为 `active` 或 `disabled` |
| 超级管理员 | 管理租户，并在显式选择租户后管理该租户业务数据 |
| 租户管理员 | 只能管理账号所属租户的业务数据，不能切换租户或调用租户管理接口 |
| 套餐（Plan） | 决定首次激活后授权时长的定义 |
| 生成批次（Batch） | 一次由管理员发起的批量激活码生成记录 |
| 激活码（Code） | 隶属一个应用和套餐、可绑定一个设备的授权凭证 |
| 设备绑定 | 激活码保存设备指纹的 HMAC，表示当前允许使用授权的设备 |
| 自助解绑 | 当前绑定设备主动释放绑定，并消耗一次迁移次数 |
| 手动解绑 | 管理员释放绑定，不消耗用户迁移次数 |
| 派生状态 | 不直接存入 `status`，由多个字段和当前时间计算出的 `disabled`、`expired` 等展示状态 |

## 核心不变量

- 完整激活码只在生成成功响应中出现一次，数据库和日志只保存 HMAC 或后缀。
- `app_secret` 只在创建或更换成功响应中出现一次，数据库只保存 HMAC。
- 设备指纹只用于计算 HMAC，不得写入数据库、日志或响应。
- 一个激活码只能属于一个应用和一个套餐。
- 一个应用必须属于一个租户；批次、激活码和日志通过应用继承相同租户归属。
- 任何管理端资源查询和按 ID 写入都必须带租户约束，不能只依赖前端筛选。
- `activated_at` 和 `expires_at` 只在首次激活时确定；后续解绑、重绑、禁用或启用不得重算。
- 激活码删除是不可恢复的软删除；删除后不能激活、校验、解绑、启用或禁用。
- 应用禁用会阻止所有客户端授权操作，但不改写该应用下激活码的原始状态。
- 需要审计的管理操作和客户端授权结果使用稳定动作和结果值写入日志；日志不得扩大敏感数据暴露面。

## 状态模型

激活码状态由四个相互独立的维度组成：

| 维度 | 字段 | 含义 |
| --- | --- | --- |
| 生命周期 | `status` | `unused`、`active`、`deleted` |
| 管理开关 | `disabled_at` | 非空表示管理员禁用 |
| 时间有效性 | `expires_at` | `active` 且 `expires_at <= now` 表示过期 |
| 设备绑定 | `device_hash` | `active` 时非空表示已绑定，空表示等待重新绑定 |

持久化生命周期只允许：

```text
unused -> active -> deleted
unused ----------> deleted
```

禁止 `active -> unused`、`deleted -> active` 和 `deleted -> unused`。

管理后台展示状态按以下优先级计算，避免一个激活码同时显示多个主状态：

1. `status = deleted` -> `deleted`
2. `disabled_at IS NOT NULL` -> `disabled`
3. `status = active AND expires_at <= now` -> `expired`
4. `status = active` -> `active`
5. 其他 -> `unused`

“已解绑待重绑”不是独立主状态，而是 `status = active`、未过期、`device_hash IS NULL` 的绑定子状态。

## 套餐与到期时间

| 套餐 | 到期计算 |
| --- | --- |
| `weekly` | 首次激活时间加 7 天 |
| `monthly` | 首次激活时间加 1 个自然月 |
| `quarterly` | 首次激活时间加 3 个自然月 |
| `yearly` | 首次激活时间加 1 个自然年 |

- 到期时间从首次激活时刻计算，不从生成时间计算。
- 自然月和自然年保留激活时分秒；目标月份不存在对应日期时，使用目标月份最后一天。
- 到期判断使用 `expires_at <= now`，到达该时刻即视为失效。
- 已解绑后重新绑定只恢复设备关系，不延长授权。

## 客户端决策表

在判断激活码前，所有客户端接口必须先验证应用：应用存在、状态为 `active`、`app_secret` 匹配。任一条件失败都不得继续授权操作。

### 激活

| 激活码条件 | 结果 |
| --- | --- |
| `deleted` | 拒绝，`CODE_DELETED` |
| 已禁用 | 拒绝，`CODE_DISABLED` |
| 已过期 | 拒绝，`CODE_EXPIRED` |
| `unused` | 写入首次激活时间、到期时间和当前设备，成功 |
| `active` 且绑定当前设备 | 幂等成功，返回原授权信息 |
| `active` 且绑定其他设备 | 拒绝，`DEVICE_MISMATCH` |
| `active` 且未绑定设备 | 原子绑定当前设备，保留原授权时间，成功 |

### 校验

| 激活码条件 | 结果 |
| --- | --- |
| `deleted`、已禁用或已过期 | 按对应稳定错误拒绝 |
| `unused` | 拒绝，`INVALID_CODE` |
| `active` 且未绑定设备 | 拒绝，`DEVICE_MISMATCH`，必须先激活重绑 |
| `active` 且绑定其他设备 | 拒绝，`DEVICE_MISMATCH` |
| `active` 且绑定当前设备 | 成功，返回授权信息 |

### 自助解绑

仅当激活码为 `active`、未删除、未禁用、未过期、已绑定当前设备时才继续判断迁移限制：

| 条件 | 结果 |
| --- | --- |
| `rebind_count >= 3` | 拒绝，`REBINDS_EXCEEDED` |
| 距 `last_rebind_at` 少于 24 小时 | 拒绝，`REBINDS_TOO_FREQUENT` |
| 其他 | 原子清空设备绑定，`rebind_count + 1`，更新 `last_rebind_at`，成功 |

解绑成功后保留 `status = active`、`activated_at` 和 `expires_at`。新设备必须调用激活接口完成重新绑定。

## 管理规则

### 应用

- 创建应用时生成 `app_id` 和 `app_secret`；仅明文密钥一次性返回。
- 禁用应用后，客户端获取应用信息、激活、校验和解绑均失败。
- 更换密钥后旧密钥立即失效，新密钥一次性返回，并记录 `rotate_app_secret`。
- 只有不存在激活码、生成批次和操作日志引用时才能物理删除应用；已有授权数据的应用应禁用。

### 激活码

- 单次生成数量为 1 到 300；服务端必须保证批次内和数据库内唯一。
- 生成结果中的明文 `codes` 只在本次成功响应展示，前端必须提示立即保存。
- 禁用不改变 `status`、激活时间、到期时间或设备绑定；启用后恢复原生命周期状态。
- 单个删除和批量删除均为软删除。
- 批量删除、禁用或启用一次最多接收 100 个唯一 ID，允许部分 ID 未更新；返回 `requested` 和 `updated`。
- 管理员手动解绑只允许操作已激活、有效且已绑定设备的激活码；不增加 `rebind_count`，不修改 `last_rebind_at`。

### 管理员

- 登录成功签发 8 小时 JWT。
- 登录必须同时提交租户名称或 slug、用户名和密码；管理员只能在所属租户下登录。
- 修改密码要求新密码至少 8 位且与当前密码不同；成功后前端清理登录态并重新登录。
- 密码恢复只适用于 `ADMIN_BOOTSTRAP_USERNAME` 对应管理员，必须同时验证 `ADMIN_BOOTSTRAP_PASSWORD`。
- 恢复后的新密码至少 8 位，且不能与恢复密钥相同。
- bootstrap 管理员只用于初始化和恢复，不应依赖弱默认密码运行生产环境。
- bootstrap 管理员是属于默认租户的超级管理员；迁移前已有管理员升级为超级管理员，已有应用归入默认租户。
- 租户管理员登录和使用已有 JWT 时都要求所属租户启用。
- 超级管理员的业务操作要求显式租户上下文，不能默认跨租户聚合或写入。

### 租户

- 只有超级管理员可以创建、修改、启用、禁用和删除租户，以及重设租户管理员密码。
- 创建租户时必须同时创建一个初始租户管理员；用户名全局唯一，密码至少 8 位。
- `slug` 全局唯一，只允许 2 到 63 位小写字母、数字和连字符。
- 禁用租户后，租户管理员登录、已有管理会话和该租户所有客户端授权请求都被拒绝；不会改写应用或激活码状态。
- 只有没有应用的非默认租户可以删除；删除时同时删除其租户管理员。默认租户不可删除。

## 日志规则

- 客户端激活、校验和解绑在找到所属激活码后记录成功或失败结果。
- 管理员批量生成、应用状态、密钥更换、激活码状态、删除和手动解绑记录成功日志。
- 日志动作值以 `worker/src/constants.ts` 为准；新增动作必须同步前端筛选和 `docs/API.md`。
- 面向管理后台的日志消息使用中文，错误统计依赖稳定 `error_code`，不要通过解析 message 判断结果。
- 可记录 `device_hash`，不得记录设备指纹、完整激活码、`app_secret`、管理员密码或恢复密钥。

## 并发与幂等

- 首次激活和未绑定设备重绑必须使用带状态条件的原子更新；并发竞争失败返回 `CONFLICT`。
- 同一设备重复激活同一有效激活码是幂等成功，不增加解绑次数、不改变授权时间。
- 自助解绑的设备匹配和次数上限必须在写入条件中再次约束；24 小时冷却由 service 在写入前根据 `last_rebind_at` 校验。
- 生成批次只在所有激活码成功持久化后返回明文结果；唯一性冲突应返回 `CONFLICT` 并要求重试。

## 规则变更要求

修改本文件中的行为时，至少同步检查：

- `worker/src/service.ts` 的判断顺序和返回错误。
- `worker/src/repository.ts` 的原子更新条件和统计口径。
- `worker/src/constants.ts`、Worker/前端类型和 UI 状态展示。
- `worker/test/service.test.ts`、`repository.test.ts` 和时间相关测试。
- `docs/API.md`、`docs/DATABASE.md`；涉及敏感数据时再更新 `docs/SECURITY.md`。
