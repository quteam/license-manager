# 业务规则

## 产品边界

授权管理系统的核心目标是提供轻量、可部署在 Cloudflare Workers 上的激活码管理能力。当前产品范围包括：

- 多应用、多平台授权管理。
- 激活码批量生成、查询、筛选、禁用/启用和软删除。
- 内置周卡、月卡、季卡、年卡四类套餐。
- 客户端激活、校验和自助解绑迁移。
- 管理员登录、会话鉴权和密码修改。
- 管理后台查看应用、激活码和操作日志。

当前不包含以下能力，新增前需要明确需求和数据模型影响：

- 多租户组织隔离。
- 管理员角色和细粒度权限。
- 支付、订单、发票或财务结算。
- 明文激活码找回。
- 客户端 SDK 发布和版本兼容矩阵。
- 多数据库或非 Cloudflare 部署适配。

## 激活码状态

状态流转：

```text
unused -> active -> deleted
unused -> deleted
```

状态含义：

- `unused`：已生成，未激活。
- `active`：已计算过期时间；通常绑定设备，解绑迁移期间可暂时无绑定设备。
- `deleted`：已软删除，不再可用。

业务上的“已过期”不是独立存储状态，而是由 `status = active` 且 `expires_at <= now` 计算得出。

业务上的“已禁用”不是独立 `status`，而是由 `disabled_at` 是否为空计算得出。已禁用激活码保留原本的未激活或已激活状态，启用后恢复原状态。

## 激活规则

- 激活码生成时只返回一次明文。
- 数据库不得保存完整明文激活码。
- 未激活码没有 `activated_at`、`expires_at` 和 `device_hash`。
- 首次激活成功时写入 `activated_at`、`expires_at` 和 `device_hash`。
- `expires_at` 必须从首次激活时间计算，不得按生成时间计算。
- 已激活但已解绑的激活码再次调用激活时只重新绑定当前设备，不得重算 `activated_at` 或 `expires_at`。
- 周卡按 7 天计算；月卡按 1 个自然月计算；季卡按 3 个自然月计算；年卡按 1 个自然年计算。
- 自然月和自然年到期时间保留激活时刻；如果目标月份没有对应日期，到期日取目标月份最后一天。
- 同一设备重复激活同一激活码应返回当前授权信息，不应重复消耗状态。
- 已删除激活码不能激活。
- 已禁用激活码不能激活。
- 已过期激活码不能重新激活。
- 禁用状态的应用不能激活。

## 校验规则

- 已激活且未过期的激活码只能被绑定设备校验。
- 已激活但已解绑的激活码不能校验为有效授权，需要先在新设备重新激活绑定。
- 未激活激活码不能校验为有效授权。
- 已删除激活码不能校验。
- 已禁用激活码不能校验。
- 已过期激活码不能校验。
- 禁用状态的应用不能校验。

## 解绑迁移规则

自助解绑迁移是客户端能力，约束如下：

- 只有已激活、已绑定设备、未禁用、未删除、未过期的激活码可以解绑。
- 请求必须提供当前设备指纹，且必须匹配当前绑定设备。
- 解绑成功后清空 `device_hash`，保留 `status = active`、`activated_at` 和 `expires_at`。
- 新设备使用同一激活码调用激活接口完成重新绑定，授权有效期不重新计算。
- 每个激活码最多允许 3 次解绑迁移。
- 相邻两次有效解绑之间必须至少间隔 24 小时。
- 解绑成功后必须记录 `rebind_count`、`last_rebind_at` 和操作日志。

## 批量生成规则

- `quantity` 范围为 1 到 300。
- 服务端按分块批量写入激活码，避免单次请求产生过多串行 D1 写入。
- 激活码必须全局唯一。
- 生成结果中的明文 `codes` 仅限本次响应展示。
- 前端必须提示用户及时保存生成结果。

## 管理规则

- 激活码删除必须使用软删除，不得物理删除。
- 应用删除仅允许删除没有激活码、生成批次或操作日志引用的应用；已有授权数据的应用应先禁用而不是删除。
- 应用密钥可由管理员更换；更换后旧密钥立即失效，新密钥只在本次响应展示，并记录操作日志。
- 激活码可禁用或启用；删除后的激活码不可再启用。
- 管理员可在激活码列表手动解绑已激活、未禁用、未删除、未过期且已绑定设备的激活码；手动解绑不消耗用户自助解绑次数，不更新 `last_rebind_at`。
- 激活码批量删除、禁用和启用每次最多操作 100 个 ID；删除仍为软删除，已删除激活码不能启用或禁用。
- 操作日志消息面向管理后台展示，新增日志应使用中文消息；码相关日志的应用信息应能通过日志或激活码关联展示。
- 管理员修改密码后应清理当前登录态并要求重新登录。
- 默认 bootstrap 管理员只用于初始化；生产环境不应依赖弱默认密码。
